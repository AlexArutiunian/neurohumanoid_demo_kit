# WearBench-G1: регистрация телеметрии Unitree G1

[English](README_ENG.md)

Инструменты для записи и проверки телеметрии суставных приводов и инерциального датчика Unitree G1. Данные предназначены для анализа механических нагрузок и сопоставления измерений с моделированием.

## Совместимость

| Операционная система | Python | ROS 2 |
| --- | --- | --- |
| Ubuntu 20.04 | 3.8 | Foxy |
| Ubuntu 22.04 | 3.10 | Humble |

Регистратор использует Unitree SDK2 и DDS. ROS 2 не требуется для записи `LowState`.

Требуется установленный и настроенный `unitree_sdk2py` с работающим CycloneDDS, а также сетевой доступ к роботу. Скрипты не устанавливают зависимости и не изменяют системное окружение. Совместимость исходного кода проверена для Python 3.8 и 3.10; получение сообщений на конкретном роботе проверяется отдельно.

## Состав

| Файл | Назначение |
| --- | --- |
| `record_lowstate.py` | Запись сообщений `LowState` в CSV и метаданных в JSON |
| `check_environment.py` | Проверка Python, SDK2, CycloneDDS и сетевого интерфейса |
| `validate_run.py` | Проверка целостности и временных характеристик CSV |
| `README_ENG.md` | Инструкция на английском языке |

## Получение проекта

```bash
cd ~
git clone --depth 1 --single-branch \
  -b wearbench-sensors-only \
  https://github.com/AlexArutiunian/neurohumanoid_demo_kit.git \
  wearbench_sensors
cd ~/wearbench_sensors
```

Скрипты ищут пакет SDK2 в текущем Python и в каталогах `~/unitree_sdk2_python_custom`, `~/unitree_sdk2_python`. Другой путь указывается через `--sdk-dir`.

## Проверка окружения

```bash
python3 --version
python3 -m py_compile record_lowstate.py validate_run.py check_environment.py
python3 record_lowstate.py --self-test
ip -br addr
python3 check_environment.py --iface eth0
```

Параметр `--iface` должен соответствовать сетевому интерфейсу, через который доступен робот.

Если SDK2 расположен в другом каталоге:

```bash
python3 check_environment.py \
  --iface eth0 \
  --sdk-dir ~/unitree_sdk2_python_custom
```

## Регистрация данных

Первую запись рекомендуется выполнить при неподвижном роботе:

```bash
python3 record_lowstate.py \
  --iface eth0 \
  --seconds 30 \
  --label stand_001 \
  --out-dir ~/wearbench_g1_data
```

Параметры:

- `--iface`: сетевой интерфейс
- `--topic`: DDS-топик, по умолчанию `rt/lowstate`
- `--seconds`: длительность регистрации
- `--label`: обозначение экспериментального запуска
- `--out-dir`: каталог результатов
- `--sdk-dir`: путь к существующей установке SDK2

После завершения создаются `*.csv` и `*.meta.json`. CSV содержит временные метки, `tick`, данные IMU и следующие поля для 29 приводов:

`q`, `dq`, `ddq`, `tau_est`, `temperature_0`, `temperature_1`, `vol`, `mode`, `motorstate`.

Метаданные содержат параметры записи, количество принятых и сохранённых сообщений, потери очереди и ошибки декодирования.

## Проверка записи

```bash
ls -lh ~/wearbench_g1_data

python3 validate_run.py \
  ~/wearbench_g1_data/ИМЯ_ФАЙЛА.csv
```

Проверяются формат CSV, временные интервалы, последовательность кадров и корректность основных числовых полей. Результат включает оценку частоты регистрации.

Если сообщения не поступают, необходимо проверить сетевой интерфейс, активный топик и настройки DDS. Альтернативный топик `rt/lf/lowstate` следует использовать только после проверки типа публикуемых сообщений.

## Ограничения измерений

- `tau_est` представляет собой оценку момента из SDK, а не результат калиброванного измерения момента на выходном валу
- Температурные поля сохраняются в исходном представлении SDK
- Тип `LowState_` не содержит отдельного канала измерения тока каждого привода
- Данные исправного робота позволяют исследовать профили нагрузок, но сами по себе не определяют физический ресурс приводов

## Безопасность

Регистратор использует `ChannelSubscriber` и не публикует команды управления. Его запуск не меняет режимы робота и не инициирует движения.

Первые измерения выполняются на неподвижном роботе. Запись в ходе движения допускается только при штатном управлении и соблюдении требований безопасности эксплуатации.
