# WearBench-G1: запись телеметрии исправного робота

Изолированный экспериментальный регистратор для RA-L. Ветка создана от `json-ctrl` без изменений работающего JSON-контроллера.

## Что учтено из существующих файлов

- `debug_history/arm_sdk_control_conflict.md`: конкурирующие писатели в `rt/arm_sdk` ранее вызывали вибрации и рывки суставов. **Здесь нет издателей DDS, команд управления, запуска плееров и переключения режимов**
- `robot_home/joints_xyz/lowstate_dump_unitree_50hz.py`: проверены `ChannelFactoryInitialize`, `ChannelSubscriber("rt/lowstate", LowState_)` и индексы 29 суставов
- `robot_home/unitree_sdk2_python_custom/.../_MotorState_.py`: `q`, `dq`, `ddq`, `tau_est`, `temperature[2]`, `vol`, `mode`, `motorstate`
- `.../_LowState_.py`: 35 `motor_state`, `tick`, `imu_state`; используем первые 29, как в существующем `joints_xyz`
- `.../_IMUState_.py`: `quaternion[4]`, `gyroscope[3]`, `accelerometer[3]`, `rpy[3]`, `temperature`

### Ограничения

`tau_est` не является лабораторно измеренным моментом на выходном валу. Значения `temperature[0]` и `temperature[1]` сохраняются отдельно как исходные поля SDK: их аппаратную интерпретацию и единицы сначала проверяем на конкретном роботе. `vol` это значение поля SDK, не обязательно напряжение батареи. **Токи приводов этот LowState IDL не предоставляет**, поэтому в этой версии они не записываются. Моторы Inspire тоже не включены в 29 Unitree-суставов.

Это не калибровка закона физического износа и не доказательство оставшегося срока службы.

## Безопасный запуск на роботе

Лучше взять **отдельную папку**: не выполнять `scripts/install_to_robot.sh` и не копировать поверх имеющихся файлов `~/unitree_sdk2_python_custom`.

```bash
cd ~
git clone --branch wearbench-g1-readonly-telemetry --single-branch \
  https://github.com/AlexArutiunian/neurohumanoid_demo_kit.git neurohumanoid_wearbench
cd ~/neurohumanoid_wearbench

# Без импорта SDK и без связи с роботом
python3 -m py_compile robot_home/wearbench_g1/record_lowstate.py \
  robot_home/wearbench_g1/validate_run.py
python3 robot_home/wearbench_g1/record_lowstate.py --self-test

# Пассивная запись 30 с в режиме стояния
python3 robot_home/wearbench_g1/record_lowstate.py \
  --iface eth0 --seconds 30 --label stand_001 \
  --out-dir ~/wearbench_g1_data
```

Если зависимости `unitree_sdk2py` не импортируются, не переустанавливай окружение действующего JSON-плеера наугад. Скрипт ищет vendored SDK внутри `robot_home/unitree_sdk2_python_custom`. Зависимости этого SDK в текущей ветке: `cyclonedds==0.10.2`, `numpy`, `opencv-python`. Используй уже установленный и проверенный на G1 Python, а при необходимости создай отдельное окружение после проверки совместимости CycloneDDS. ROS2 для данного регистратора **не требуется**, `source /opt/ros/.../setup.bash` не нужен.

Укажи фактический интерфейс: `ip -br addr`. В репозитории для робота используется `eth0`, но имя не гарантировано на каждой установке. При отсутствии сообщений через 10 секунд регистратор завершится с ошибкой и метаданными. Проверь сетевой интерфейс и тип сообщения; вариант `--topic rt/lf/lowstate` допустим лишь после проверки соответствия источника.

Регистратор автоматически завершает запись по `--seconds`; `Ctrl+C` останавливает раньше и сохраняет данные. Он **никогда не посылает** команд в `rt/arm_sdk` / `rt/lowcmd`.

## Проверка сохранённого CSV

```bash
python3 robot_home/wearbench_g1/validate_run.py \
  ~/wearbench_g1_data/ИМЯ_ФАЙЛА.csv
```

В конце опыта создаются:
- `YYYYMMDD_HHMMSS_stand_001.csv`: каждая полученная запись LowState без искусственного downsampling, два временных штампа, tick, 29 суставов, IMU
- `YYYYMMDD_HHMMSS_stand_001.meta.json`: режим, источники, число сообщений, потери очереди, ошибки декодирования, причина остановки

Для научного эксперимента исключай повреждённые/неполные записи. Не интерпретируй повторный приём в новом callback как независимый опыт, особенно если это один и тот же `tick`; валидатор контролирует временные метки и пропущенные порядковые номера, а дубли `tick` надо проверить по файлу отдельно.

## Следующие записи для RA-L

1. `stand_001`: неподвижный G1, 30 с; удостовериться в каналах и температуре
2. `stand_002`: повтор для оценки шума/дрейфа
3. `arms_slow_001`: безопасное штатное движение руками, решение о запуске принимает оператор
4. `walk_slow_001`: только если оператор допускает штатную ходьбу с достаточной страховкой и пространством
5. `cooldown_001`: покой после движения, без принудительного охлаждения

Запускай уже имеющийся **единственный** контроллер как обычно; WearBench только слушает. Не стартуй два управляющих процесса. Не назначай из этого проекта кнопкам джойстика новых функций.

Для сопоставления с MuJoCo сохраняй `q`, `dq`, `tau_est`, IMU, исходные температуры и синхронизацию. `|tau_est*dq|` можно исследовать как **оценочный work-like proxy**, но его физическая интерпретация требует проверки величины и знака момента.

## Что проверено и что нет

- **Проверено по исходному SDK**: имена полей IDL, схема 35 моторных каналов и порядок первых 29 из прежнего `joints_xyz`
- **Реализовано**: read-only подписчик и сохранение CSV без SDK-публикации
- **Ещё не подтверждено на живом G1**: доставка DDS-сообщений в этой версии скрипта, фактическая частота, семантика temperature и `tau_est`, синхронизация с конкретным штатным motion

Прежде чем использовать данные в статье, проведи короткий опыт стояния и пришли `.meta.json` + начало CSV. По ним решим, нужен ли адаптер под реальную конфигурацию G1.
